# 可追溯历史与长会话读取

`events.jsonl` 是原始事件的单一来源。`SessionHistory` 提供消息、事件和归档分页，模型工具与 UI 的 JSON-RPC 共用它；不另建一套对话或“记忆”存储。本次不加入产品 `/goal`。

## 查询

模型可以省略 `session_id`，直接查询当前会话：

```text
history_search(pattern="Windows Terminal")
history_read(event_id="搜索结果中的 event_id")
history_read(turn_id="结果中的 turn_id")
history_read(reverse=true)
artifact_read(artifact_ref="tools/输出归档路径")
```

`history_search` 使用不区分大小写的字面文本，不使用正则表达式。默认检索用户、助手和工具消息；`messages_only=false` 同时检索内部事件，包括中断时尚未提交成消息的输出检查点。消息视图保留返回的 reasoning 和工具调用信息，内部事件保留事件身份与原始载荷的文本投影。

每条结果带稳定的 `event_id`、`seq`、`turn_id`、归档引用，以及本段的字符偏移和总长度。`next_cursor` 继续同一查询；搜索扫描一批记录没有命中时仍可能返回游标，不能将它当成搜索结束。按事件读取也可以分页，单个大输出不会突破页面预算。改变查询条件时重新开始，不复用旧游标。

默认内容预算 12,000 字符；每页还限制记录数和包含 JSON 转义、元数据的记录编码总量（24,000 字符，外层分页信息另计）。因此大量空消息或转义字符也不会制造无限大的工具响应。

归档的 `next_cursor` 保存文本流定位信息，后续分页直接定位；旧的字符 `offset` 仍可用，但会从头跳过相应字符。保留 Unicode 和原始换行，字符总数到 EOF 才确定。归档改变后旧游标会报错，需重新读取。

历史和归档工具已经自行分页，因此输出截断钩子不再二次截断或归档它们，续读游标始终保留。归档每次使用独立身份，模型重复使用工具调用 ID 也不会覆盖旧结果。归档写入、会话恢复和历史查询共用会话 ID 校验及目录映射；Windows 下写入也保持原始换行，使归档内容与校验和一致。

## 索引与恢复

每个会话的 `.history.sqlite3` 只是可删除重建的派生索引，保存事件身份、轮次和 4,096 字符文本块。首次查询按最多 8 MiB 的日志批次建立索引；批次在完整 JSONL 记录边界结束，所以单个历史大事件可以超过该预算。后续只解析追加部分，查询单条大消息只加载对应文本块。搜索每次最多扫描 256 个块，未命中内容和内部事件也占扫描预算。

`indexed_bytes` / `source_bytes` 报告实际索引进度。倒序查询先建到日志尾部，避免将旧记录误认为最新记录；调用方可在分页请求之间继续处理输入。

未完成的末行保持待读，`awaiting_tail=true` 明确表示等待写入完成，不应紧密轮询。完整但损坏的 JSON 行计入 `skipped_records`，后续有效记录仍可读取。文件替换或截断会重建索引。意外的结构或数据库错误直接报告，不添加多层静默降级。

摘要使用已有的精确消息出处匹配，保存源会话、事件 ID 和检查点引用；模型补充摘要时不能改写这些出处或原始用户请求。旧摘要仍可读取。历史是过去的记录，既不重新授权旧指令，也不证明当前工作已通过验证。

## TUI

启动和 `/session` 恢复时，主页只接收最近三轮用户对话的有界预览：最多
128 条原始条目，每条 JSON 编码不超过 64 KiB，预览列表总计不超过 256 KiB
（按 UTF-8 字节计，包含 JSON 转义和省略提示）。优先保留较新的条目；超长
内容显示开头及截短提示，省略较早条目时额外显示一条提示。该限制只作用于
展示，模型上下文、已保存消息和中断输出记录保持完整，可通过历史分页继续读取。

F2 会话详情内按 `h` 打开历史。`n/p` 翻页，`/` 搜索，方向键选择，Enter 打开原文；`m` 切换消息与事件，`a` 打开该记录的归档，`r` 刷新。页面通过 `history.read` / `history.search` / `history.artifact` 请求后端，回复带会话代数；切换会话后旧页面不会被当成新会话数据。读取历史不会写入主页，也不会覆盖草稿。

主页将大消息分成文本块，按可见范围排版，并使用最多 6,000 行的 LRU 缓存。未访问部分只保留高度估计，滚动提示用 `~` 标记估计总行数；访问后按实际排版修正。按记录和块定位保持阅读位置，追加输出、改变宽度和展开内容无需排版所有旧记录。连续工具最多 128 次一组，以限制单组折叠和失败摘要的处理量。

此处限制的是查询页面、排版缓存和渲染工作。实时会话原文仍保留在前端状态中，后端恢复与模型运行也仍使用既有的内存 ledger；本次没有把运行时改成完全从磁盘按需恢复。完整原文不会因缓存淘汰而被删除。

验证覆盖：万条消息、数百万字符的单条流式输出、浏览期间追加、宽度变化、缓存上限、真实 Python RPC 与 Ink 历史操作、摘要出处回查、索引增量更新、文件替换、损坏末行，以及 Unicode / 换行 / JSON 转义的完整分页。

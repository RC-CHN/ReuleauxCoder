# LSP 诊断投递

成功的 `edit_file` / `write_file` 排队一个文档提交请求。后台 worker 按顺序同步文件、发送 didSave、获取诊断；编辑工具默认最多等待 1 秒，优先把本次请求已到达的诊断附到工具的 `model_content`，保留原有工具返回内容和结构化诊断。即时投递的批次确认消费后，不再通过请求尾部重复注入。

工具侧等待超时或取消只停止等待，不取消后台诊断，也不把已成功的编辑改成失败。晚到的结果仍在后续模型请求的易变尾部注入。空诊断或被严重程度配置全部过滤的结果静默消费；不会伪造错误已清空的文本。

LSP 客户端通过诊断到达通知唤醒等待者，已到达的结果立即读取，不再固定轮询 100ms。等待仍按文件和诊断代次匹配，超时返回空结果，取消直接传播；取消等待不会消费之后才到达的诊断。

即时诊断随工具结果进入模型历史，之后遵循通用工具输出截断、归档和上下文保留策略。尾部兜底注入不改写已有工具消息或稳定历史前缀：只有最终请求仍包含该投影、并且批次消费确认成功时，才报告已注入；预算检查失败或注入被后续 hook 移除时，不消费批次。工具和请求竞争同一批次时，未取得消费权的一方不投递自己的注入。

## 限制

```yaml
lsp:
  edit_wait_timeout_ms: 1000
  max_diagnostics: 20
  max_message_chars: 1000
  max_injection_chars: 12000
  include_warnings: true
```

- `edit_wait_timeout_ms`：编辑工具等待本次诊断的时间上限，包含排队和服务器启动时间；设为 0 时仅尝试读取已经就绪的结果。后台诊断自身仍使用 `poll_timeout_ms` 等待新发布。
- `max_diagnostics`：每文件保留条数，先按严重程度和位置排序，再截取。
- `max_message_chars`：每条消息保留的首行字符数，包括缩短标记；XML 转义前计算。
- `max_injection_chars`：整段自动注入的硬字符上限，包含 XML 包装、诊断结果和截断说明，最小值为 512。
- 整批预算优先保留错误；省略与缩短数量同时写入投影和 UI 提示。被 `include_warnings: false` 过滤的非错误诊断不算已注入。

即时投递和尾部兜底共用诊断投影限制；等待时间及三个投影限制都可以通过 `/config` 查看有效值和来源。字符预算不是精确 token 预算；模型请求仍受已有的总预算检查约束。

原始诊断保留在运行时事件和会话记录中，TUI 默认显示数量，F4 查看完整内容。模型可以调用 `lsp_diagnostics` 重新查询当前文件的诊断；主动查询走通用工具输出截断与归档，不受自动注入的每文件条数上限约束。

批次仍按 agent、会话代次和会话 ID 隔离；同文件的新结果替换旧结果，待消费结果每个 owner 最多 32 批、保留 300 秒。超过投影预算的内容在明确报告省略后随批次消费，不会在每轮重复投递。超时与服务不可用是独立结果，不表示原有错误已清空。

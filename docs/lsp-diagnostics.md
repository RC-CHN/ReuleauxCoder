# LSP 诊断投递

成功的 `edit_file` / `write_file` 只排队一个文档提交请求。后台 worker 按顺序同步文件、发送 didSave、获取诊断，编辑工具不为此等待。已到达的诊断统一在下一次模型请求的易变尾部注入，尚未到达的结果留待后续请求。

LSP 客户端通过诊断到达通知唤醒等待者，已到达的结果立即读取，不再固定轮询 100ms。等待仍按文件和诊断代次匹配，超时返回空结果，取消直接传播；取消等待不会消费之后才到达的诊断。

注入不改写工具的 `model_content` 或稳定历史前缀。只有最终请求仍包含该投影、并且批次消费确认成功时，才报告已注入；预算检查失败或注入被后续 hook 移除时，不消费批次。两个请求竞争同一批次时，未取得消费权的请求移除自己的注入。

## 限制

```yaml
lsp:
  max_diagnostics: 20
  max_message_chars: 1000
  max_injection_chars: 12000
  include_warnings: true
```

- `max_diagnostics`：每文件保留条数，先按严重程度和位置排序，再截取。
- `max_message_chars`：每条消息保留的首行字符数，包括缩短标记；XML 转义前计算。
- `max_injection_chars`：整段自动注入的硬字符上限，包含 XML 包装、诊断结果和截断说明，最小值为 512。
- 整批预算优先保留错误；省略与缩短数量同时写入投影和 UI 提示。被 `include_warnings: false` 过滤的非错误诊断不算已注入。

三个限制都可以通过 `/config` 查看有效值和来源。这些是字符预算，不是精确 token 预算；模型请求仍受已有的总预算检查约束。

原始诊断保留在运行时事件和会话记录中，TUI 默认显示数量，F4 查看完整内容。模型可以调用 `lsp_diagnostics` 重新查询当前文件的诊断；主动查询走通用工具输出截断与归档，不受自动注入的每文件条数上限约束。

批次仍按 agent、会话代次和会话 ID 隔离；同文件的新结果替换旧结果，待消费结果每个 owner 最多 32 批、保留 300 秒。超过投影预算的内容在明确报告省略后随批次消费，不会在每轮重复投递。超时与服务不可用是独立结果，不表示原有错误已清空。
